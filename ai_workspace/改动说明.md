## 三、美术风格做了什么

配色**故意保持**你原来的 `linen` 底色 + `burlywood` 导航栏，没有换成别的色系。

- **设计变量集中管理**：颜色、圆角、阴影、间距全在 `风格.css` 顶部的 `:root` 里。
  想整体调风格，改那一段就够了，不用翻每个页面。
- **阴影换成暖色投影**：原来用的是 `rgba(0,0,0,...)`，在米色纸上会显脏；
  现在带一点红黄（`rgba(122,94,62,...)`），并做了 1/2/3 三级层次。
- **文字用暖褐代替纯黑**：`#3b3026` 打底，避免纯黑在米色底上过于刺眼。
  正文（`#txtBox`）换成宋体 + 2.1 倍行距，读小说舒服很多。
- **子页面结构与样式统一**：6 个子页面原来各自抄了一份几乎相同的 CSS，
  现在共用 `风格.css`，以后改一处全站生效。
- **顶栏**：burlywood 改成上浅下深的渐变，加了一道顶部高光，
  并改成 `sticky`（滚动时导航栏一直留在顶上）。
- **侧边栏菜单**：条目左侧加了状态竖条，带子菜单的项加了会翻转的箭头，
  子菜单用虚线做出「树枝」的感觉，点击过的条目会高亮（新加的 `.current`）。
- **首页卡片**：改成 `auto-fit` 网格，自动适配列数；悬停时上浮 + 顶部渐变色带展开。
- **导航 logo**：原来靠 `transform: scale(2)` 硬撑，图会溢出导航栏。
  现在按原图实际内容（2048×2048 里文字只占 569px 高）算出合适尺寸，
  用 `.logo-slot` 的 `overflow: hidden` 裁掉透明留白，位置和大小可预期。
- **动效**：内容切换、卡片入场加了淡入；同时用
  `prefers-reduced-motion` 照顾关掉动画的用户。

## 四、顺手修掉的问题

这几处不是审美问题，是会真的影响使用，所以一并处理了：

1. **小说正文原本挤成一整段** — `txtBox.innerText = text` 写进去的换行，
   在默认 `white-space: normal` 下会全部被合并成空格。
   现在 `#txtBox` 用 `white-space: pre-wrap`，`.txt` 的段落和换行正常显示。
   （Markdown 走 `innerHTML`，不能套这个规则，所以单独用 `.md` 类区分。）

2. **`主页.html` 的 doctype 写成了 `< ! DOCTYPE html>`** — 空格会让浏览器进入
   quirks 模式，已修正。同时修好了 8 个页面里写法错误的
   `<meta name="viewport" content="width=device-width", initial-scale=1.0>`
   （逗号在引号外面，`initial-scale` 根本没生效），移动端现在能正常缩放。

3. **首页那张 `are you lost` 墙纸其实一直没显示** — 它写在 `body::before` 上并给了
   `z-index:-1`，会被 body 自己的背景盖掉。现在改到 `html` 上，body 用半透明暖色覆盖，
   墙纸和 `background-blend-mode: multiply` 一起把白底染成亚麻色。

4. **左上角有个莫名其妙的小图标** — 自定义光标 `.mouse` 一开始停在 `left:0;top:0`，
   鼠标没动之前会在角落露出来。现在初始位置放到屏幕外。

5. **按 B 退出烟花模式后版式会坏** — `花火.js` 里写死了一份 `originBodyStyle`，
   退出时把旧版的内边距、背景、`display:flex` 等当成行内样式塞回 `<body>`，
   行内样式优先级最高，新的样式表会被整个盖住。
   现在改成退出时逐条 `removeProperty`，让 CSS 重新接管 —— 以后再改版式也不用动这个文件。

6. **`技术.html` 的点击回调漏了 `async`** — 里面的 `await import()` 会让整个
   `<script>` 报语法错误，导致该页所有菜单都点不动。这是我在重写过程中引入的，
   已修好并逐页验证过。

7. **窄屏适配**：原来首页是写死的 `1000×500`、卡片 `400×200`，
   手机上会横向溢出。现在宽度用 `min(1040px, 100% - 32px)`，
   侧边栏在 820px 以下改为上下堆叠。

# 第二轮：修「打砖块」点不开 + 改成适配的美术风格

## 一、点不开的真正原因

**跟样式无关**，是因为打砖块是全站唯一用 ES module 加载的东西：

```js
const module = await import(`./${filePath}`);
```

用 `file://` 直接打开网页时，ES module 会被 CORS 拦掉（页面 origin 是 `null`）：

```
Access to script at 'file:///.../game-breakout.js' from origin 'null' has been blocked
TypeError: Failed to fetch dynamically imported module
```

而 `鼠标.js`、`花火.js` 都是普通 `<script src="...">`，不受这个限制，所以只有游戏挂掉。

顺带确认：`fetch()` 在 `file://` 下同样会被拦，所以**直接双击打开网页时，
`文学/技术/数学` 的正文也加载不出来**。要么用本地服务器，
要么这次的改动至少把游戏救回来了（普通脚本在 `file://` 下是能跑的）。

## 二、这一轮改了什么

| 文件 | 改动 |
|------|------|
| `game-breakout.js` | 由 ES module 改成**普通脚本**，挂到 `window.BreakoutGame`；整体重新配色绘制 |
| `技术.html` | 用注入 `<script>` 的方式懒加载游戏（`loadScript()`），并**补回被漏掉的停止逻辑** |
| `风格.css` | `#txtBox canvas` 补上 `height: auto`、暖色纸底和描边 |

**游戏画面**：砖块改成「上排奶油/焦糖 → 下排藕粉/玫瑰」的暖色渐变，
圆角 + 底部厚度 + 顶部高光；挡板是焦糖渐变胶囊；球是粉色带柔光和拖尾；
画布加了一层纸面底色和顶部暖光，和卡片风格统一。
另加了左上角「剩余砖块」和右上角「移动鼠标控制挡板 · 按住 S 减速」提示。

**顺手修的小问题**：
- 补回 `技术.html` 原有的 `txtBox._module.stop()`（第一轮重写时漏掉了，
  会导致切走菜单后游戏还在后台空转）。顺序也改成**先 stop 再清空 DOM**。
- 挡板坐标按画布实际缩放换算（窄屏画布被 CSS 缩小后，挡板原来会跑偏）。
- 加了触摸支持（`touchmove`），手机上也能玩。
- 挡板碰撞改成只在球下落时判定，并回弹到挡板上方，避免高速时卡住；
  击球点偏离中心会改变横向角度，手感更自然。
- 画布 `height: auto`，窄屏等比缩放而不是被压扁。

## 三、验证情况

|------|------|
| `http://` 打开 → 点打砖块 | canvas 出现，游戏正常跑 |
| `file://` 打开 → 点打砖块 | **修复前：无 canvas、报 CORS 错；修复后：正常** |

# 第三轮：新增小游戏「花瓣占卜」

## 一、新增了什么

「技术 → 小游戏」下多了一个 **花瓣占卜**（`game-hanauta.js`）。

玩法就是你要的：

- 每次随机开一朵花，**花瓣数随机**（5–13 片）
- 下面一个主按钮，点一下掰掉一片花瓣，按钮在 **好き / 嫌い** 之间来回切
- **颜色也跟着切**：好き 是粉（呼应 `sera&milu` 的 logo），嫌い 是蓝（logo 里的那抹蓝）
- 花瓣掰完为止，**最后一片掰掉时的那个词就是结果**，按钮变成结论并停住
- 旁边一个 **重置** 按钮，重新随机开一朵

细节：

- 每掰一片，花会轻轻转到下一片花瓣朝上，花瓣飘落、淡出，花心还会抖一下
- 剩几片花瓣实时显示（「还剩 N 片花瓣」）
- 出结果时按钮放大发光；**好き** 会飘一捧粉色小爱心，**嫌い** 是几点蓝色小光点
- 整朵花在轻微呼吸摇摆；花心按黄金角铺了花蕊小点
- 画布按设备像素比放大绘制，Retina 上也是清晰的

## 二、为了加这个游戏，动了两处公共代码

1. **游戏加载器改成注册表**。原来 `技术.html` 的 `loadScript()` 写死了
   `resolve(window.BreakoutGame)`，加第二个游戏就得改加载器。
   现在每个游戏脚本用**自己的真实 URL** 当键注册到 `window.SiteGames`，
   加载器按 `el.src` 取。好处是**以后再多的游戏都不用动加载器**，
   脚本改名或挪进子目录也不会失效。
   `game-breakout.js` 也跟着换成了这种注册方式（只有末尾三行）。

2. **`风格.css` 加了一节 `.hanauta-*`**：状态文字、结果文字、
   主按钮（`.is-like` 粉 / `.is-dislike` 蓝 / `.is-done` 结果态）、重置按钮、
   以及窄屏下按钮改成竖排。同时给新加的一节重新排了序号。

## 三、踩到并修掉的坑

**Retina 屏上画布会变成两倍大。** 按设备像素比放大绘制时，
`canvas.width = 520 * dpr` 会让浏览器把 canvas 按**属性宽度**显示，
于是在 DPR=2 的屏幕上整朵花渲染成 887px 宽而不是 520px。

实测对比：

| 设备像素比 | 修复前显示尺寸 | 修复后显示尺寸 |
|---|---|---|
| 1 | 522 × 562 | 520 × 560 |
| 2 | **887 × 955** | 520 × 560 |

修法是显式写 `canvas.style.width = W + 'px'` 把显示尺寸钉死，
位图仍然是 `W × dpr`，所以既大小一致又清晰。

## 四、验证情况

| 场景 | 结果 |
|------|------|
| 点开花瓣占卜 | 花朵正常绘制，按钮出现 |
| 连续点击主按钮 | 文字与颜色逐次切换，花瓣逐片减少 |
| 掰到最后一瓣 | 停在该词（不是翻转后的反面），按钮变为结果态并禁用 |
| 结束后再点 | 无任何变化 |
| 点重置 | 重新随机开花（第二次得到的花瓣数不同） |
| 结果正确性 | 12 片时结果「嫌い」= 第 12 片花瓣的词，符合交替规则 |
| DPR 1 / 2 | 显示尺寸都是 520 × 560，Retina 下清晰 |
| 420px 窄屏 | 画布等比缩放，两个按钮竖排占满 |

> 小提醒：桌面宠物 Miku 是 `position: fixed` 跟着屏幕底部走的，偶尔会飘到
> 结果文字或按钮前面挡住视线。它 `pointer-events: none`，**不影响点击**，
> 等它走开就行。

# 第四轮：花瓣占卜 · 去掉片数 + 改成倾斜视角

## 一、去掉了「还剩 N 片花瓣」

你说得对——知道总数就能直接推算出结果（片数奇偶决定最后一个词），
占卜就没悬念了。现在游玩过程中**状态栏不显示任何数字**：

- 只在还没开始时显示一句「点下面的按钮，一片一片掰下去」
- 掰下第一片之后就变为空白（元素保留，`min-height` 撑着，避免出结果时布局跳动）
- 只有掰完才出现「結果：好き ♡ / 結果：嫌い…」

`remaining` 变量仍然在内部记账（判定何时结束），只是不再往界面上写。

## 二、花盘改成倾斜面向用户的透视

原来是俯视的平面圆（花心是正圆、花瓣均匀铺满一圈）。
现在把整个花盘在 y 方向压扁，做出「花面朝向观众、微微仰起」的角度。

具体做法：

| 参数 | 作用 |
|------|------|
| `TILT = 0.72` | 花盘整体在 y 方向的压缩比。1 = 正对镜头，越小越躺平 |
| `BACK_LEN = 0.84` | 背面的花瓣离观众更远，再额外缩短一点，拉开前后纵深 |
| `CORE_R = 38` | 花心半径，同时决定花瓣从哪里长出来 |

绘制顺序上也做了调整：

1. 花瓣从**花盘边缘**（`CORE_R * 0.45`）长出来，而不是从圆心
2. **花心最后画**，所以花盘是一整块完整的脸，不会被花瓣切碎

中途试过「花心夹在前后花瓣中间」的画法，结果花心被前排花瓣压掉一半、
整个花盘糊成一坨（第一版 `TILT = 0.66` 就是这样），所以改成现在这样。

飘落的花瓣也同步修正：初始角度要按 `atan2(ay, ax)` 反算压扁后的角度，
否则花瓣会按「未压扁」的角度斜着飞出去。

## 三、验证情况

| 场景 | 结果 |
|------|------|
| 游玩全程 | **不出现任何数字**（脚本断言 `anyNumberWhilePlaying = false`） |
| 8 片 | 第 8 片为「嫌い」→ 结果为「嫌い」，符合交替规则 |
| 掰到最后一片 | 按钮变为结果态并禁用，再点无变化 |
| 重置 | 重新随机开花，回到「好き」并重新显示提示语 |
| 倾斜视角 | 花心呈椭圆形、上排花瓣更短，读起来是花面朝向观众 |
| 掰完 | 只剩椭圆花盘 + 绿色花萼，像个小种托 |
| JS 异常 | 无 |

# 第五轮：花可以切换样式了（波斯菊 / 玫瑰 / 彼岸花）

## 一、加了什么

游戏顶部多了一排胶囊按钮，点一下换一种花，目前三种：

| 花 | 做法 |
|----|------|
| **波斯菊**（默认） | 尖花瓣 + 金黄花粉盘，就是原来那朵 |
| **玫瑰** | 宽圆花瓣、基部深边缘浅、带一点兜起来的暗弧；花心是**卷起来的内层花瓣**（每圈起止角都不同，否则会画成靶心）；茎上还加了三根刺 |
| **彼岸花** | 细长并向上翻卷的花被片 + **七根比花瓣还长的雄蕊**（这是它最标志性的特征）；**没有叶子**——彼岸花「花不见叶」，所以只有一根光茎 |

换花会重开一局；点「重置」会保留当前选的花。

## 二、实现方式：样式表

花的差异全部收进文件顶部的 `STYLES` 数组，一种花一个对象：

| 字段 | 作用 |
|------|------|
| `tilt` / `backLen` | 倾斜程度、背面花瓣缩短比例（每种花可以不一样，彼岸花更侧一点） |
| `coreR` / `petalBase` | 花心半径、花瓣从花盘半径的多少倍处长出来 |
| `len` / `wid` | 花瓣长度与宽度的随机范围 |
| `path(len, wid)` | 花瓣轮廓 |
| `paint(len, wid)` | 填色 / 描边 / 脉络 |
| `center(r)` | 花心 |
| `extra()` | 附加零件（彼岸花的雄蕊就走这里） |
| `stem(headX, headY)` | 茎和叶子 |

**想再加一种花，照着一个对象写进 `STYLES` 就行**，切换按钮会自动多出来一个，
加载器和页面都不用改。透视、掰花瓣、飘落、结果判定这些逻辑都是共用的。

## 三、中途修正的两处

1. **玫瑰的花心一开始画成了靶心**——五圈同心圆弧等距排开，看着像射击靶。
   改成每圈用不同的起止角、交替配色，才像卷起来的花心。
2. **彼岸花的花瓣一开始太短**，被雄蕊压过去了。加长加宽之后花头才有分量。

# 番外：真 3D 原型（`原型_3D花.html`）

**这个不在正式站点里**，是独立的一页，双击即可打开（three.js r160 UMD 就放在
`ai_workspace/lib/`，不联网也能跑）。用来验证「真 3D 值不值得换掉现在的 2D 版」。

## 一、做了什么

- 花瓣是**代码生成的参数化曲面**：中心线是一段逐段积分出来的曲线（`turn` 控制
  总转角，超过 π 就会向内翻卷），横截面沿法线贴上去，再绕长轴 `roll` 扭转
- 真·透视相机 + 三盏灯，可以拖拽旋转、滚轮缩放
- 三种花：波斯菊 / 玫瑰（带内圈装饰层）/ 彼岸花（细带花瓣 + 长雄蕊，没有叶子）
- **颜色可调**：9 个预设色点 + 一根色相滑杆
- **🌈 疯狂变色**：色相每帧往前推，整朵花原地狂变颜色

## 二、几个关键设计

**颜色只覆盖色相和饱和度，保留每种花自己的明暗关系。**
所以同一套控制下玫瑰还是深的、波斯菊还是浅的，不会整朵拍平成一个颜色。
另外 `satOverride` 是**倍率不是绝对值** —— 花瓣基部色和尖端色饱和度差很多，
盖成一个绝对数会把渐变里的浓淡对比抹平，整朵花发灰（第一版就是这样）。

**疯狂变色不能每帧重建几何。** 顶点色改成「原地重算」：
建几何时记下每个顶点在渐变里的位置 `ts`，之后每帧只改 `color` attribute 就行
（整朵花共用一份花瓣几何，所以一次更新覆盖全部花瓣）。
走 `rebuild()` 的话每帧新建几何，直接卡死。

## 三、踩过的坑（已记进 CLAUDE.md）

1. **逐项列举参数的调用处**：`makePetalGeometry` 的参数改名后，配置和函数体都改了，
   唯独调用处还在传旧名字，新参数全部走默认值 —— 花瓣永远是平的。
   表现是「怎么调都没反应」。**这个坑踩了两次**（花瓣一次、叶子一次），
   最后改成 `Object.assign({...}, f.petal)` 整体展开传参。
2. **验证截图没关缓存**：有几轮「改了没效果」其实是拿到了旧页面。
3. **靠肉眼判断卷曲**：卷曲在竖直平面里，正对镜头看就是一条线。
   改成读几何包围盒（`y` 范围几乎为 0 = 平的）才定位到问题。

## 四、现状与结论

3D 版**能跑、可交互、可调色**，但还没到「比 2D 好看」的程度：

- 花瓣是零厚度曲面，转到侧面就是纸片
- 材质只有基础 `MeshStandardMaterial`，缺花瓣该有的半透明感
- 光照一开始给太硬（平行光 2.1），平坦花瓣每个面一块死高光，像低多边形折纸；
  把环境光提到 2.0、平行光降到 0.85 才柔和下来

**是否替换 2D 版还没定**，等看完原型再决定。
